# Codex 下载与安装分阶段进度设计

## 目标

把当前“下载并安装 Codex”单一操作拆成两个可独立理解、独立重试的阶段。用户先下载并校验 OpenAI 官方文件，成功后再主动开始系统安装。整个过程显示当前阶段、文件级进度、总体进度和带时间的详细记录，不再用一条容易混淆的状态文字同时代表下载与安装。

## 方案

保留现有三步主向导：`安装 Codex → 配置 DeepSeek → 完成`。只在第一步内部增加两个连续子阶段：

1. 下载并校验官方文件。
2. 使用已经校验的文件安装 Codex。

不增加新的主向导页面，避免顶部步骤变成四步或五步。下载成功后停留在第一步，主按钮由“下载官方文件”切换为“安装 Codex”。安装成功后才进入 DeepSeek 配置页。

## 下载阶段

“下载官方文件”依次完成：

- 检查 Windows、账户模式、AppX 服务和系统盘空间；
- 检查本地缓存或内部版相邻 `payload`；
- 下载 `ChatGPT-x64.msix`；
- 下载 `ChatGPT-License.xml`；
- 校验下载来源、MSIX 包身份、架构、版本和签名；
- 保存本次运行内的已验证文件引用。

下载区域显示：

- 当前文件名；
- 当前阶段标题和详细说明；
- 单文件已下载字节数、总字节数和百分比；
- 下载速度与预计剩余时间；
- 总体阶段进度；
- 每条带本地时间的详细记录。

速度使用相邻两次下载报告的字节差和时间差计算，并用平滑后的每秒字节数显示。总大小未知时显示已下载大小和不确定进度，不伪造百分比或剩余时间。

本地缓存或内部版相邻文件仍须重新执行完整校验，但不显示虚假的网络速度。校验失败时不启用安装按钮。

## 安装阶段

“安装 Codex”只消费本次运行中已经成功校验的文件，不重新下载。安装进度按以下固定阶段显示：

1. 准备 Windows 管理员授权；
2. 等待用户确认 UAC；
3. 部署官方 MSIX 和离线许可证；
4. 为当前 Windows 用户注册应用；
5. 准备和验证 Codex CLI；
6. 保存不含秘密的安装记录；
7. 安装完成并进入 DeepSeek 配置。

安装进度是阶段进度，不伪装成系统 cmdlet 的精确字节百分比。每完成一个阶段更新总体百分比和详细日志。UAC 前继续明确说明要求的是 Windows 管理员密码，不是 DeepSeek API Key。

## 状态模型

第一步增加以下状态：

- `NotDownloaded`：允许下载，不允许安装；
- `Downloading`：只显示下载进度，禁用会改变流程的按钮；
- `ReadyToInstall`：文件已校验，允许安装或重新下载；
- `Installing`：只显示安装阶段进度；
- `InstallFailed`：保留已校验文件，允许直接重试安装；
- `Installed`：进入 DeepSeek 配置。

重新打开助手时不会相信内存中的旧验证结果。它可使用磁盘缓存缩短下载，但必须重新校验后才能进入 `ReadyToInstall`。

## 进度数据

扩展现有 `SetupProgress`，至少包含：

- 进度类别：检查、下载、校验、授权、部署、注册、CLI、完成；
- 简短标题；
- 详细说明；
- 当前文件名；
- 当前字节数与总字节数；
- 当前百分比与总体百分比；
- 是否为不确定进度。

ViewModel 根据原始字节和时间计算展示文本，不把 API Key、凭据内容、完整命令行或敏感响应写入日志。详细记录最多保留最近 200 条，避免长时间运行无限占用内存。

## 界面

第一步卡片包含：

- 顶部两个子阶段标签“1 下载并校验”“2 安装 Codex”，当前阶段高亮；
- 当前操作标题与详细说明；
- 单文件进度条及大小、速度、预计时间；
- 总体进度条及百分比；
- 主按钮区域：下载阶段显示“下载官方文件”，准备完成后显示“安装 Codex”；
- 可展开的“查看详细记录”，逐条显示时间、阶段与结果；
- 失败区显示原因以及明确的“重试下载”或“重试安装”。

实验性解包按钮仍只在正式安装失败后出现，并使用已校验的文件，不重复下载。

## 错误与重试

- 下载或校验失败：停留在下载阶段，安装按钮保持禁用；重试只重新准备文件。
- UAC 被取消：保留已验证文件，停留在安装阶段，可直接再次点击安装。
- 系统部署或用户注册失败：保留下载结果和诊断文字，可直接重试安装或选择实验模式。
- CLI 准备失败：不重复下载；重试安装从现有已验证文件继续。
- 本次运行中缓存文件被外部修改或删除：安装前再次执行轻量存在性与签名校验，失败后回到下载阶段。

## 接口调整

`IWizardActions` 将原来的组合安装方法拆为：

- `PrepareCodexAsync(IProgress<SetupProgress>, CancellationToken)`：下载并校验，返回可安装状态；
- `InstallPreparedCodexAsync(IProgress<SetupProgress>, CancellationToken)`：只安装已验证文件；
- `InstallPreparedPortableAsync(IProgress<SetupProgress>, CancellationToken)`：只解包已验证文件。

`DesktopSetupActions` 持有本次运行的已验证 `CodexPayload`。安装方法如果没有有效载荷必须失败，不允许偷偷回退到下载。

## 测试与验收

- ViewModel 测试覆盖下载成功才启用安装、下载失败禁用安装、安装失败保留载荷、重试安装不再次下载以及安装成功进入第二步。
- 进度测试覆盖文件大小、百分比、速度、预计时间、不确定总大小和 200 条日志上限。
- Actions 测试覆盖安装接口缺少已准备载荷时失败。
- WPF 结构测试覆盖两个独立按钮、两个进度条、阶段标签和详细记录区域。
- 全量单元测试、Windows x64 WPF 编译、自包含发布和 ZIP 完整性检查必须通过。
- 最终仍需在 Windows 10 22H2 普通管理员账户真机验证下载速度显示、UAC 阶段、安装重试和可见 Codex 窗口。
