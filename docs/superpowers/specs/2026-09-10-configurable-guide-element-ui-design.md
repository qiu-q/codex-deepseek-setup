# 可配置 DeepSeek 分步引导与 Element 风格 UI 设计

## 目标

把当前直接铺在 DeepSeek 配置页中的四张模拟图片替换为可随时关闭、逐步浏览的原生 WPF 引导弹窗；内部版从现有推广后台获取引导配置，开源版以及网络异常时使用内置兜底步骤。同时统一安装助手的视觉语言，减少大圆角、大色块和过强阴影，采用接近 Element Plus 的简洁后台工具风格。

本次不修改官方 Codex，不引入 WebView，不允许后台下发 HTML、脚本、命令或本地文件路径。

## 用户流程

当向导首次进入“配置 DeepSeek”页时，自动打开分步引导弹窗。用户可以：

1. 查看当前步骤的标题、图片、说明与完成条件；
2. 点击“打开官方页面”访问该步骤配置的 HTTPS 地址；
3. 使用“上一步”和“下一步”依次浏览；
4. 随时点击右上角关闭按钮或“稍后再看”；
5. 关闭后通过配置页上的“查看操作引导”重新打开。

关闭引导不会阻止用户粘贴 API Key 或继续配置。弹窗在同一次程序运行中只自动出现一次，不反复打扰用户。最后一步的主按钮显示“完成引导”，关闭弹窗后焦点回到 API Key 输入区域。

## 弹窗设计

弹窗使用 WPF 原生 `Window`，默认约 680×560，可随系统 DPI 缩放。结构为：

- 标题栏：引导名称、当前步骤编号、关闭按钮；
- 精简步骤指示器：只显示圆点、序号和当前进度，不同时展开所有内容；
- 内容区：最大 16:9 图片、步骤标题、说明、完成条件；
- 底部操作区：“稍后再看”“上一步”“打开官方页面”“下一步/完成引导”。

远程图片加载失败时隐藏图片区域并保留文字，不显示破图。弹窗不自动打开网页，只有用户点击官方页面按钮才调用系统浏览器。

## 远程配置协议

现有 Go 服务增加公开接口：

- `GET /api/v1/guide`：返回当前启用的引导；无启用配置时返回 `204`。

管理接口增加：

- `GET /api/admin/guide`：读取引导配置；
- `PUT /api/admin/guide`：验证并原子保存引导配置。

管理后台增加“操作引导”区域，支持启停、编辑、添加、删除、上移、下移和预览步骤。图片继续复用受限媒体上传接口。

公开数据格式：

```json
{
  "version": 1,
  "enabled": true,
  "title": "DeepSeek API 使用准备",
  "steps": [
    {
      "id": "sign-in",
      "title": "登录或注册",
      "body": "使用手机号验证码或官方支持的方式登录。",
      "completionHint": "已进入 DeepSeek 开放平台控制台",
      "actionText": "打开登录页",
      "actionUrl": "https://platform.deepseek.com/sign_in",
      "imageUrl": "https://www.qiuqiuqiu.top/xxx/codex-ad/media/guide-sign-in.webp"
    }
  ]
}
```

验证约束：最多 8 步；步骤 ID 唯一且不超过 48 字符；标题不超过 60 字；说明不超过 240 字；完成条件不超过 120 字；按钮文字不超过 16 字；所有操作地址和非空图片地址必须为 HTTPS。任何无效远程数据都整体拒绝，不部分执行。

## 客户端架构

Core 增加 `IGuideClient`、`GuideDocument`、`GuideStep`、远程获取和验证逻辑。它复用广告客户端的 3 秒超时与受限图片下载原则，但使用独立类型和接口，避免推广与产品引导相互耦合。

内部版构建配置提供引导接口地址；开源版不请求远程引导。ViewModel 负责选择远程或内置文档、保证每次运行只自动显示一次，并维护当前步骤。WPF 弹窗只负责呈现和用户事件，不负责网络请求或配置验证。

客户端获取顺序：

1. 内部版异步请求远程引导；
2. 成功且数据有效时使用远程配置；
3. 超时、断网、204、无效 JSON 或无效字段时使用内置简洁文字步骤；
4. 图片逐张按需加载，单张最大 2 MB；失败仅隐藏当前图片。

不把远程引导永久写入用户目录，避免旧内容长期残留。引导请求不携带用户名、API Key、设备 ID、Codex 数据或硬件信息，也不增加引导展示统计。

## Element 风格调整

界面采用 Element Plus 的视觉原则而不是复制 Web 组件：

- 主色 `#409EFF`，成功 `#67C23A`，警告 `#E6A23C`，危险 `#F56C6C`；
- 页面背景 `#F5F7FA`，常规文字 `#303133`，次要文字 `#606266`，边框 `#DCDFE6`；
- 普通卡片圆角 4px，弹窗与主要容器 6px；
- 按钮高度统一为 36–40px，主次按钮边界明确；
- 输入框使用 1px 边框和 4px 圆角；
- 卡片主要依靠边框和留白分层，移除大面积黑色头部和夸张阴影；
- 状态信息使用轻量 Alert 样式，不用大块高饱和背景；
- 顶部标题、步骤条、正文和底部状态栏按统一 8px 间距体系排列。

现有安装、下载、维护和清理行为不变，只调整呈现层和引导入口。

## 后台界面

管理页面同样改用 Element 风格变量和紧凑布局。推广配置与操作引导放在两个清晰区块中。引导编辑器每次只展开一个步骤，包含实时预览、字符限制提示和排序按钮。保存失败时保留表单内容并显示服务器返回的具体校验错误。

后台身份验证、8 小时会话、CSRF、登录限速、媒体类型与 2 MB 上限保持不变。

## 错误处理与安全

- 公开引导接口不可用不会影响安装、DeepSeek 配置或 Codex 启动；
- 非 HTTPS 链接、超长字段、重复 ID、空步骤、未知版本和无效 JSON 均拒绝；
- 客户端绝不解释 HTML，也不执行后台下发内容；
- 图片只接受 PNG、JPEG、WebP，按最大字节数限制后再解码；
- 用户主动关闭引导后，本次运行不再自动弹出；
- 开源版完全不连接推广或远程引导接口。

## 测试与验收

Core 单元测试覆盖有效引导、204、超时、无效 JSON、HTTP 地址、重复 ID、步骤数量和字段长度。ViewModel 测试覆盖内部版远程配置、开源版兜底、首次自动显示、关闭后不重复弹出、前后翻页和最后完成。

WPF 结构测试确认旧的整页图片网格被移除，分步弹窗、关闭、上一页、下一页、官方链接和重新打开入口存在。Go `httptest` 覆盖管理接口登录/CSRF、原子保存、公开读取、禁用 204、校验失败和步骤排序保持。

发布验收继续执行 135 个既有 .NET 测试、WPF Windows 目标交叉构建、Go 测试与 `go vet`、内部版与开源版真实打包及 85 MB 体积目标。Windows 10 19045 和 Windows 11 上补充弹窗 DPI、关闭、重开、断网兜底和图片失败回归。
